# Dataset / model asset research (verified 2026-10-21 via HF API, READMEs, direct file-header reads)

Summary of corrections to the starting assumptions:
- PHANTOM is now HapticWAM; data is NOT LeRobot, it is per-episode zarr + JSON manifests.
- AIRoA MoMa: gated; two repos; the `airoa-moma` repo is LeRobot v3-style layout (not v2.1); a per-primitive-action O/X + failure-cause schema was NOT confirmed (see below).
- RH20T ports: no fingertip tactile in any port. `meta.rating` exists, range -1..9.
- REASSEMBLE: no span-style "anomaly annotation" exists; only per-segment `success` + a per-file known-issues table. Also a LeRobot v3 port exists (`robot-lev/reassemble`).
- RoboRewardBench is NOT from the FLORA paper; it is the test split of `teetone/RoboReward` (RoboReward paper, arXiv:2601.00675).
- FLORA arXiv id: NOT found (project page + PDF carry no arXiv id; arXiv API search finds nothing). Paper PDF: https://research.nvidia.com/labs/gear/flora/assets/paper/flora.pdf (dated 2026-10-20, 37 pp). Appendix G prompts were extracted from that PDF and cross-checked against released code.

## 1. PHANTOM -> HapticWAM
- Paper: arXiv:2609.23888 (ICRA 2027 submission). Code: github.com/Advanced-Robotic-Manipulation/HapticWAM (schema doc: docs/dataset_schema.md). Collection: huggingface.co/collections/armteam/hapticwam-icra-2027-6ab234bdfe24c383b5f9fb57
- Repos (all ungated, CC-BY-4.0):
  - `armteam/hapticwam-teleop-raw` (old `armteam/phantom-episodes`, renamed 2026-09-19; old id redirects). Loose, ~865,000 files (snapshot_download takes 1-3 h to enumerate; use `--include "tasks/<task>/<ep>/*"`).
  - `armteam/hapticwam-teleop-dataset` : packed one `.tar.zst` per task, ~103 GB total (Carton 14.5 GB, Carton_fail 1.5, egg 21.6, egg_fail 1.7, waffles 14.9, waffles_fail 1.8, whiteboard 15.3, whiteboard_fail 0.65, batch_20260822 30.6), plus `manifests.tar`, `manifests_v6.tar`, `norm_stats.json`, `index.jsonl`, `samples/`.
  - Others: hapticwam-sim-episodes, -rig-episodes, -rollouts, models -teacher/-student/-baselines/-ablations.
- Hardware: UR3 + Robotiq 2F-85 + 2x Daimon DM-Tac W2L fingertip sensors + RealSense scene cam; Echo exoskeleton teleop.
- Size: 1,115 eps total (1037 train/78 val); `tasks/` view = 790 eps (712/78); 8 task keys: Carton, waffles, egg, whiteboard (+ `_fail` each; 20/20/20/10 fail eps in v4, +15 each for 3 tasks in batch_20260822 under-grasp). batch_20260822 (325 eps) is in `archive/20260822_*` only, not yet in `tasks/` or manifests.
- Layout: `tasks/<task>/ep_<task>_<epoch>_<idx>/` one dir/episode: `meta.json` + one zarr group per stream, each with `data` (T,...) and `ts` (T,) master-clock seconds (not resampled; align by nearest ts). `manifests/<task>.jsonl`, `manifests/all.jsonl`, `manifests/quality_full.csv`. Raw session layout in `archive/`, `collect/` (meta.json authoritative; dir names like `carton`, `*_fail_undergrasp`).
- Streams: `camera_scene_color` (T,480,640,3) JPEG-per-frame in zarr VLenBytes, 15 Hz (NOT mp4); `tactile_{left,right}_wrench` (T,6) [Fx,Fy,Fz,Mx,My,Mz] in N and N*m (~5.7-6.5 Hz); `tactile_*_area` (T,) mm^2; `tactile_*_fields_ds` (T,72,96,8) f16 channels [disp_x,disp_y,depth,shear_x,shear_y,fx,fy,fz] (depth and distributed fx,fy,fz in raw SDK units, uncalibrated); `tactile_*_keyframes` (T,144,192,8) ~2.5 Hz; `tactile_*_infer_img` (T,288,384) u8; `arm_q`,`arm_qd`,`arm_tcp_pose`,`arm_tcp_speed`,`arm_ft` (T,6) 125 Hz (CB3 current-based estimate with large pose-dependent bias, NOT a real F/T sensor); `gripper` (T,2) ~95 Hz = [position 0 open..1 closed, Robotiq gOBJ 0..3 (2 = stopped by contact = holding)]; `actions` (T,7) 10 Hz delta-EE + gripper closure; `actions_abs` (T,7) [q_target(6), gripper]. Missing stream => no dir at all (pad-free deploy has no tactile_*).
- meta.json keys: task, text, operator, tags, policy, dagger_round, success, damage, notes, driver_modes, clock_calibration, config_hash, hardware_shapes, deploy_overrides, status (must be `finalized`), weight.
- manifests/all.jsonl row (verified): `{"episode","task","success","failure_demo","tactile_contact","split","session","operator","duration_s","peak_force_N","max_contact_mm2","path"}`. Peak force = N (SI wrench; pad ceiling ~30 N, some spikes exceed); contact area mm^2.
- Label caveats (important for success flags): v4 `*_fail` demos (over-squeeze/induced slip) have `success=true` ("captured the intended failure"); batch_20260822 `*_fail` (under-grasp) have `success=false`. Training code treats failure via `is_failure_demo()` = success false OR tag `deliberate_failure` OR task name ending `_fail`. `tactile_contact=false` = grasp landed outside pads (no tactile signal). Failure demos have higher peak force (medians 17.8-33.5 N vs 8.4-12.9 N) and contact area. Whiteboard rows in task table have blank stats.
- Caveats: no depth, single scene camera; wrist F/T is not a real sensor; tactile units raw/uncalibrated except wrench.

## 2. SharpaDex v1.0
- `Sharpa-Robotics/SharpaDex-v1.0`, ungated, license CC BY-NC-4.0, ~7.7 TB (usedStorage 7,694,812,710,261 B), 28,993 eps, 59 tasks, 495 seasons, 32.4M frames, ~300 h @30 FPS, 224,087 subtask segments, 45 skill labels. Both `lerobot_v3.0` and `lerobot_v2.1` exports of every season (same demos; don't double count).
- Layout: `<task>/season_<id>_train/lerobot_v3.0|lerobot_v2.1/{data,videos,meta}`; meta has info.json, stats.json, tasks.parquet, subtasks.parquet (v2.1: jsonl), annotations.jsonl, modality.json, annotation_cache.jsonl, episodes/, v40_validation.json. Split by season.
- Features: observation.state (65), action (65), observation.state.joint_torque (65; dims 0-57 valid, torso 58-64 zeros), observation.state.tcp (24; F/T slots always 0), observation.state.tcp_pose (12), action.tcp_pose (12), observation.tactile (60 f32), videos observation.images.{head_left,head_right,wrist_left,wrist_right} 480x480, tactile_deform 480x1200, tactile_raw 480x1600 (h264 MP4), timestamp, frame_index, episode_index, task_index, subtask_index. Subtask fields: start_step, end_step, text, task_skill, label (subtasks|hand_actions), id.
- Tactile 60-D layout (verified from info.json names): 10 fingertips x 6 (fx,fy,fz,tx,ty,tz), order left then right, each thumb,index,middle,ring,little. Indices: left_thumb fz=2, left_index fz=8, left_middle fz=14, left_ring fz=20, left_little fz=26; right_thumb fz=32, right_index fz=38, right_middle fz=44, right_ring fz=50, right_little fz=56. (fx=6k, fy=6k+1, fz=6k+2, with k = finger number 0..9.) Units not documented in the card.
- NO success/failure flag (demonstrations only; "success criteria" appear only as text tags in annotations). Caveats: tactile video streams dominate bandwidth; TCP rotation convention undeclared; per-season metadata varies.

## 3. RH20T community LeRobot v3 ports (`robot-lev/rh20t_cfg*`)
- All public, ungated, license "other" (rh20t-dual: scenes 0001-0005 CC BY-SA 4.0; scenes 0006-0010 CC BY-NC 4.0). Per-episode license from `meta/rh20t_episodes.json` (`folder` field). Contains faces/voices (audio sidecars `audio/episode_*.wav`). Unofficial; RGB only (no depth). Code: github.com/lvjonok/rh20t-lerobot-port (URL returned 404 when fetched; DECISIONS.md not retrievable). Original: arXiv:2307.00595, rh20t.github.io.
- Configs (fps 10): cfg1 flexiv 4258 eps/2.21M fr/330 GB; cfg2 flexiv 1789/0.96M/141 GB; cfg3 ur5 798/0.44M/51 GB (README says 798 eps; `total_episodes` 798); cfg4 ur5 2182/1.27M/166 GB; cfg5 franka 1225/0.57M/76 GB; cfg6 kuka 1477/0.79M/102 GB; cfg7 kuka 896/0.39M/59 GB; plus rh20t_cfg4_recovered (3 eps), rh20t_cfg4_task0064 (1 ep).
- Features (identical in every config): observation.state (14; ee_pose 7 + joint 6 + gripper 1; cfg7 joint 7 -> 15), observation.state.{ee_pose,joint,gripper}, observation.force (3), observation.torque (3), observation.robot_ft (6), action (8 = next ee_pose 7 + gripper), meta.rating (int64, 1), observation.images.cam_<serial> (360x640 video, 9-10 per config), timestamp, frame_index, episode_index, index, task_index.
- robot_ft: present in all configs but NOT clearly calibrated; stats: cfg3 min/max clipped to +-300 on several axes (std ~30/10/18 N), cfg5 range ~+-45 N, cfg7 Fz min -571 N. `observation.force`/`torque` is all zeros in cfg5 (franka) - i.e. only robot_ft available there. Source RH20T paper: F/T sensors tared and frames aligned; HF original has force_torque_base.npy with "zeroed" vs "raw". Whether the port uses zeroed or raw could not be verified (DECISIONS.md unavailable).
- meta.rating: exists, min -1 max 9 (cfg3 mean 6.77, cfg5 6.92, cfg7 7.32). -1 presumably "unrated"; semantics not documented anywhere I could find.
- Fingertip tactile: NONE of the ports carry tactile. In original RH20T, tactile (uSkin, 200 Hz) exists only in Cfg 7 (Kuka + Robotiq-85 + ATI Axia80), per paper; the port drops it.
- Also relevant: `robot-lev/reassemble`, `robot-lev/fmb`, `fmb_multi`.

## 4. REASSEMBLE
- Canonical: TU Wien Research Data https://researchdata.tuwien.ac.at/records/0ewrv-8cb44 (DOI 10.48436/0ewrv-8cb44), v1.0.0 (2025-04-25), CC-BY-4.0, ungated. Files: data.zip 58.9 GB (HDF5), poses.zip 89 KB, splits.zip 1 KB, README.txt. Paper arXiv:2502.05086; code github.com/TUWIEN-ASL/REASSEMBLE; page tuwien-asl.github.io/REASSEMBLE_page/. (Zenodo id 0ewrv-8cb44 does not exist.)
- 149 recordings (HDF5, named `YYYY-MM-DD-HH-MM-SS.h5`; matching `<name>_poses.json`), 4,551 demonstrations (4,035 successful), 781 min, NIST Task Board 1, Franka, 17 objects, 4 actions (pick, insert, remove, place).
- HDF5: top-level `hama1`,`hama2`,`hand` (mp4 bytes), `hama*_audio`/`hand_audio` (mp3), `capture_node` (event cam mp4), `events` (N x 3: x,y,polarity); `robot_state/{compensated_base_force, compenseted_base_torque [sic], gripper_positions, joint_efforts, joint_positions, joint_velocities, measured_force, measured_torque, pose, velocity}`; `timestamps/<sensor>` (N x 1 each, own rates, F/T ~1.7 kHz measured); `segments_info/<i>/{start,end,success,text}` with `Low_level/<j>/{start,end,success,text}` (timestamps in seconds on the sensor clock; i/j = order index). - Anomaly annotation: no span/frame-index anomaly format exists. The only anomaly info is (a) per-segment `success` Boolean, (b) README "known issues" table per file: hand cam missing (2025-01-10-15-28-50, -16-17-40, -17-10-38), no empty action at beginning (01-10-17-54-09, 01-11-14-22-09), F/T not valid for last action (01-11-14-45-48, -15-27-19, -15-35-08), gripper broke for last action (01-13-11-16-17), pose unavailable for last action (01-13-11-18-57). Repo advertises "anomaly detection" as a task enabled by success labels.
- Community port `robot-lev/reassemble` (CC-BY-4.0, LeRobot v3, 149 eps, 1.43M frames @30 fps, cams hand/hama1/hama2/event_cam; observation.force/torque (3), observation.force.base/torque.base (gravity-compensated), segment.success (bool), segment.index; F/T nearest-neighbour downsampled 1.7 kHz->30 fps; audio/events sidecars; low-level segments not exposed as columns; per-frame task = high-level segment text).

## 8. RoboRewardBench
- Not FLORA's; it is the human-verified test split of `teetone/RoboReward` (ungated, CC-BY-4.0, total 27 GB, 54,135 ex.: train 45,072 / val 6,232 / test 2,831). Paper arXiv:2601.00675; leaderboard crfm.stanford.edu/helm/robo-reward-bench/v0.0.1/. FLORA uses it (MAE 40.0 x100 vs Astra 55.4, RoboReward 66.5).
- Format: `{train,val,test}/metadata.jsonl` (HF videofolder) with `file_name` (mp4 path under split dir, e.g. `austin_sirius_dataset_converted_externally_to_rlds/..._train_index_527.mp4`; some named `..._attempt_1_score_2.mp4`), `task` (instruction), `reward` int 1-5 (1 no success .. 5 perfect), `gpt5_mini_check` (text). Test split ~0.58 GB for 1000 listed files in tree (truncated listing); 2,831 rows in test/metadata.jsonl.
- Source corpora: Open X-Embodiment + RoboArena, with counterfactual relabeling and temporal clipping for negatives.
- Also in FLORA: RobometerBench (robometer.github.io; 567 OOD trajectories), DenseRewardBench/RubricBench are internal (40 episodes each; not released).

## 9. NVIDIA FLORA
- Paper: "FLORA: An Open Model Suite for Scaling Robotics Data Engines" (Leng, Man, Li, ... Zhu, Bjorck, Fan), dated 2026-10-20. arXiv id NOT found. Project: research.nvidia.com/labs/gear/flora/ ; PDF https://research.nvidia.com/labs/gear/flora/assets/paper/flora.pdf ; PDF fetchable and its Appendix G (G.1-G.6) contains the verbatim prompts.
- HF collection `nvidia/flora`: models `nvidia/Flora-Rewarder` (27B, Qwen3.5-27B base, Qwen3_5ForConditionalGeneration, BF16, 11 safetensors shards ~5.3 GB each ~54 GB), `nvidia/Flora-Captioner` (27.36B), `nvidia/Flora-TempSeg`. Ungated. License NVIDIA OneWay Noncommercial License (22 Mar 2022); research only.
- Flora-Rewarder model card: describes outputs and sizes but contains NO prompt text and NO code snippet. Real inference code is in the repo `batch_utils/` (core.py, terminal_reward.py, dense_reward.py, rubric_reward.py, engine.py, requirements.txt, examples/jobs.jsonl). Requirements: vllm==0.24.0, transformers==5.8.1, qwen-vl-utils==0.0.14, decord==0.6.0, av>=15, numpy<3, Pillow>=11,<13, huggingface_hub>=1.0; Python 3.12; 1x H100 80GB for outcome/dense, 2 for rubric; first run compiles kernels for minutes. Run: `python -m batch_utils.terminal_reward --jobs jobs.jsonl --output terminal.jsonl [--with-rationale]` and `python -m batch_utils.dense_reward ...`; job line `{"id","task","videos":[...]}`; camera videos must be synchronized and native fps; `--dry-run` prints first prompt.
- Modes: outcome = 1-5 score (up to 64 frames, <=10 fps, mosaic of <=4 views; progress=(E[score]-1)/4 from top-20 logprobs); dense = 1/2/3 per 0.5 s on 16 s windows (64 frames @4 fps, stride 10 s, retrospective, offline only); rubric = 1 video per camera at 2 fps (code) / 1 fps (paper), ANSWER: [...], 9 samples medoid. Model card says benchmarks: RoboRewardBench MAE 40.0, RobometerBench OOD tau-a 72.0.
- Verbatim prompts: see /private/tmp/claude-501/-Users-orengershony-Projects-tactile-flora/3af4ccfb-e754-4536-9c42-1660e4a08fb1/scratchpad/research/flora_prompts.md. Local copies of the source files: .../research/flora_src/ and the paper text .../research/src/flora_layout.txt.
